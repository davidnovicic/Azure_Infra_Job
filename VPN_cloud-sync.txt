ON-PREM MIGRATION TO AZURE USING AZURE CLOUD SYNC

Configure IP Forawrding on Linux

cat /proc/sys/net/ipv4/ip_forward needs to be 1

sudo sysctl -w net.ipv4.ip_forward=1

sudo nano /etc/sysctl.d/99-firewall.conf

add this line into 99-firewall.conf :
net.ipv4.ip_forward=1

apply the configuration:
sudo sysctl --system

check the routing:

ip -br addr
ip route

WE CREATE TROUGH TERRAFORM:

Azure side
-VPN Gateway
-local gateway
-VPN connection

On-prem side
inside Linux machine:

sudo apt update
sudo apt install -y strongswan
ipsec --version
sudo nano /etc/ipsec.conf

configuration of ipsec:

config setup
    charondebug="ike 2, knl 2, cfg 2"

conn azure-s2s
    type=tunnel
    auto=start

    keyexchange=ikev2
    authby=psk

    left=%defaultroute
    leftid=68.210.224.110
    leftsubnet=10.10.0.0/16

    right=68.210.34.71
    rightid=68.210.34.71
    rightsubnet=10.20.0.0/16

    ike=aes256-sha256-modp2048
    esp=aes256-sha256-modp2048

    keyingtries=%forever
    dpdaction=restart
    dpddelay=30s
    dpdtimeout=120s
	
	
create preshared key:
sudo nano /etc/ipsec.secrets
68.210.224.110 68.210.34.71 : PSK "YOUR_VPN_SHARED_KEY"
sudo chmod 600 /etc/ipsec.secrets
ls -l /etc/ipsec.secrets
sudo systemctl restart strongswan-starter
sudo systemctl status strongswan-starter --no-pager

check if the connection is established:
sudo ipsec statusall

troubleshoot if connection is not established:
sudo journalctl -u strongswan-starter -n 100 --no-pager

the VPN connection is not goint to work because our 
on-prem VM is behind NAT, and IPSEC cannot work where there is NAT
in front of the VPN router, that's why we have to use
forceencaps=yes to encapsulate IPSEC with UDP (4500) so it can work with NAT

after that restart the strongSwan service:
sudo systemctl restart strongswan-starter


ROUTING ON-PREM TO AZURE AND ROUTING FROM AZURE TO ON-PREM

-we have to create two routing tables and routes inside for each direction, and attach it to
the subnets
-make sure security groups are allowing traffic for specif 
protocols and ports

Before we join the computers to domain , we have to add
on the Cloud Vnet a custom DNS server (dns on domain contoller),
also if we want to test connection from domain contoller(on-prem) to 
Client W11 machine on the cloud , we have to enable inbound firewall
rules on the Client W11 machine with already configured 
Network Secutiry Groups and routing.
